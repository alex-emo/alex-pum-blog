# OPT-10 渐进增强：无 JS 可评论、邮箱防混淆

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 预计工时 | 2 h |
| 涉及文件 | `app/templates/partials/comments.html`、`app/templates/partials/profile_card.html`、`app/templates/base.html`、`app/static/js/comments.js` |
| 风险 | 低 |

## 问题

### 1. 无 JS 无法评论

`partials/comments.html`：

```html
<button type="button" id="comment-open" class="btn-primary comment-open">发表评论</button>
<form id="comment-form" class="comment-form" novalidate hidden>
```

表单默认 `hidden`，只能靠 `comments.js` 展开。**JS 被拦截 / 加载失败 / 用户禁用时，评论功能完全不可用**——而评论恰恰是最需要"网络差也要能用"的功能。

### 2. 邮箱被第三方脚本改写

线上页脚邮箱渲染成：

```html
<a href="/cdn-cgi/l/email-protection#dfbeb3baa7ee...">[email protected]</a>
```

这是 Cloudflare 的 **Email Address Obfuscation** 注入，配合 `email-decode.min.js`（1.2 KB）还原。后果：

- 无 JS 用户看到的是 `[email protected]` 乱码；
- 给 CSP 多一个第三方脚本例外；
- 多一个外部请求和解析开销。

### 3. 评论表单的其他细节（可一并处理）

- `novalidate` 关掉了浏览器原生校验，但 JS 里未必做了等价提示——需要确认 `comments.js` 在空昵称/空内容时是否有可见错误。
- 验证码图片 `alt="验证码图片，点击刷新"` 写得好，但没有键盘可达的"刷新"按钮。
- 回复按钮是一级回复（`data-parent`），没有"取消回复"的可见状态。

## 方案

### 1. 表单默认可见，JS 负责折叠（渐进增强的正确方向）

改法：服务端渲染时表单是**可见的**，JS 加载成功后才把它折叠并挂上「发表评论」按钮。

```html
<form id="comment-form" class="comment-form">   <!-- 去掉 hidden -->
  ...
</form>
```

```js
// comments.js 顶部
var form = document.getElementById('comment-form');
var openBtn = document.getElementById('comment-open');
// 只有 JS 跑起来才折叠
form.hidden = true;
openBtn.hidden = false;
```

服务端模板里 `openBtn` 初始 `hidden`，`form` 初始可见。这样：

- 有 JS：折叠 + 按钮（当前行为）；
- 无 JS：表单直接可用，按钮不出现。

> 另一个更简单的选择：表单一直可见，去掉按钮。评论区在页面底部，多占几百像素无伤大雅。如果产品上不喜欢，就用上面的方案。

### 2. 关闭 Cloudflare 邮箱混淆

Cloudflare 面板 → **Scrape Shield → Email Address Obfuscation → 关闭**。

关闭后邮箱在 HTML 里是明文，会被爬虫抓。取舍：

- **可以接受**：个人博客的公开联系方式本来就该被抓；`security.txt` 里已经是明文。
- **想防**：改成 `mailto:` 图片、或链接到 `/about` 页面用表单，或 `&#64;` 实体 + 不提供 mailto。

推荐：**关闭混淆**，页脚换成纯文本 `alex12141327@163.com`（不加 mailto，减少点击误触），联系方式详细说明放 `/about`。

### 3. 评论相关补充

- 加"刷新验证码"按钮（`<button type="button" aria-label="换一张验证码">`），不依赖点击图片。
- 提交失败时用 `aria-live="polite"` 区域播报错误，读屏可感知。
- `novalidate` 改成保留原生校验（去掉 `novalidate`），或 JS 里补等价的 `reportValidity()`。

### 4. 侧栏搜索

`<form class="profile-search" action="/search" method="get">` 已经是**原生 GET 表单**，无 JS 可用 ✅——这是做得对的地方，可作为评论表单的改造范本。

## 验收

- [ ] Chrome DevTools → Settings → Disable JavaScript，刷新文章页：**表单可见、可直接提交**，验证码图片可显示（图片由服务端生成，不依赖 JS）。
- [ ] 恢复 JS：行为与现在一致（按钮展开）。
- [ ] 页脚邮箱在无 JS 时显示为正常邮箱文本。
- [ ] CSP 下不再加载 `email-decode.min.js`。
- [ ] 键盘用户可以用 Tab 到"刷新验证码"按钮并生效。
