# 博客优化提案（总览）

> 提案编号：OPT-2026-11
> 提交日期：2026-11-05
> 对象：`blog.pum.org.cn`（本地仓库 `blog/`，FastAPI + Jinja2 + SQLite + Cloudflare Tunnel）
> 依据：本地只读实例 + 线上站点实测（响应头、Chrome 资源计时、多宽度布局检查、可访问性树与目标尺寸测量、对比度计算）
> 参考：Web Vitals、WCAG 2.2、MDN CSP、IndieWeb Webmention

---

## 一、评估结论

站点完成度远高于一般个人玩具：SSR + 语义化 HTML、三态深浅色无闪屏、全文 RSS、JSON-LD、SQLite WAL + 每日备份、后台 CSRF/HttpOnly、评论验证码 + 蜜罐 + 限流，骨架都在。

短板集中在三处：

1. **读请求里同步写库** —— 性能与稳定性耦合；
2. **静态资源体积失控** —— MathJax 单文件 2.1 MB、头像 87 KB；
3. **WCAG 2.2 / SEO 的细节收尾** 没做完。

综合评分：**7.5 / 10**（个人博客范畴内，属于"好看、能用、但没走到最后一公里"）。

## 四、里程碑建议

### M1：止血（P0，约 10 h，一周内）

OPT-01 → OPT-05。目标是消除 500 风险、把数学页体积砍掉一个量级、补上分享图与安全头、让监控能正常探活。
完成标准：数学页解码体积 < 800 KB；`HEAD /` 返回 200；`securityheaders.com` 评级 ≥ A；分享卡片出图。

### M2：达标（P1，约 12 h，两周内）

OPT-06 → OPT-11。目标是通过 WCAG 2.2 AA 的自动化检查（axe 0 错误）、首页图片负载 < 30 KB、LCP 图片有 `srcset`。
完成标准：axe / Lighthouse Accessibility ≥ 95；Lighthouse Performance ≥ 95（首页）。

### M3：打磨（P2，约 22 h，按月滚动）

OPT-12 → OPT-16。属于长期增值项，按兴趣排期。

## 五、通用约定

- **改一项、验一项**：每个任务完成后跑 `venv/bin/python -m scripts.smoke_test`，并 `curl -I` 复核响应头。
- **不要一次性改色值**：对比度调整会牵动 pygments 主题与深色模式，改完必须两种主题各截一次图。
- **备份先行**：涉数据库的改动（OPT-01、OPT-13）前先 `venv/bin/python -m scripts.backup`。
- **回归清单**：每个任务条目末尾的"验收"一节即为回归清单，不通过不开下一个任务。
- **记录实测**：修改后的数字请回填到对应任务条目的"实测结果"表格，保持提案与事实同步。

## 六、已确认的非问题（避免误判）

- 本地只读挂载下文章页 500（`attempt to write a readonly database`）是**沙箱环境现象**，不是代码缺陷；但它精确演示了 OPT-01 描述的失败模式。
- 移动端侧栏折叠、无横向溢出、深色模式对比度、系统字体栈（无 webfont）都是**做得好的部分**，优化时不要动。
- `media/` 已用 `immutable` 一年缓存，无需改动。
