# OPT-13 搜索升级：LIKE → SQLite FTS5

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 预计工时 | 3 h |
| 涉及文件 | `app/services/posts.py`、`app/migrations/`（新增 `m000x_fts.py`）、`app/routers/pages.py` |
| 风险 | 中（涉及数据库迁移与索引重建） |

## 问题

`post_service.list_posts(keyword=...)` 用 `LIKE` 匹配**标题 + 摘要**：

```python
or_(Post.title.ilike(f"%{keyword}%"), Post.summary.ilike(f"%{keyword}%"))
```

局限：

1. **搜不到正文**——读者记得一句话但记不住标题，就搜不到；
2. `LIKE '%x%'` **无法走索引**，全表扫描，文章几百篇后每搜一次就扫一次；
3. 没有相关度排序、没有高亮、没有分词，中文按 2-gram 容易误命中。

## 方案

### 1. FTS5 + trigram 分词（对中文友好的最省事选择）

```sql
-- migrations/m0005_fts.py
CREATE VIRTUAL TABLE posts_fts USING fts5(
  title, summary, content,
  content='posts',
  content_rowid='id',
  tokenize='trigram remove_diacritics 2'
);
```

- `trigram` 分词器：无需外部分词器，对中英文都能做子串匹配，SQLite ≥ 3.34 自带；
- `content='posts'`：外部内容模式，不重复存正文；
- 通过触发器保持同步：

```sql
CREATE TRIGGER posts_ai AFTER INSERT ON posts BEGIN
  INSERT INTO posts_fts(rowid, title, summary, content)
  VALUES (new.id, new.title, new.summary, new.content);
END;
CREATE TRIGGER posts_ad AFTER DELETE ON posts BEGIN
  INSERT INTO posts_fts(posts_fts, rowid, title, summary, content)
  VALUES('delete', old.id, old.title, old.summary, old.content);
END;
CREATE TRIGGER posts_au AFTER UPDATE ON posts BEGIN
  INSERT INTO posts_fts(posts_fts, rowid, title, summary, content)
  VALUES('delete', old.id, old.title, old.summary, old.content);
  INSERT INTO posts_fts(rowid, title, summary, content)
  VALUES (new.id, new.title, new.summary, new.content);
END;
```

迁移脚本里 `INSERT INTO posts_fts(posts_fts) VALUES('rebuild');` 回填历史数据。

### 2. 查询

```python
stmt = (
    select(Post, func.bm25(posts_fts).label("rank"))
    .join(posts_fts, posts_fts.c.rowid == Post.id)
    .where(posts_fts.match(keyword))
    .where(Post.status == PostStatus.PUBLISHED)
    .order_by("rank")
    .limit(limit).offset(offset)
)
```

注意：

- `bm25()` 返回负数，越负越相关（`ORDER BY rank` 升序即相关度降序）；
- 用户输入要转义：双引号、`*`、`:` 在 FTS5 查询语法里有含义。最稳妥是**整句加双引号**当作短语匹配：

```python
def fts_query(q: str) -> str:
    q = q.replace('"', '""')
    return f'"{q}"'
```

- `trigram` 分词器要求查询 ≥ 3 个字符；1–2 字的查询回退到原来的 `LIKE`。

### 3. 摘要与高亮（可选）

FTS5 的 `snippet(posts_fts, 2, '<mark>', '</mark>', '…', 32)` 可以返回带高亮的摘要片段，比现在统一显示 `summary` 字段更有信息量。但需要前端配合 `<mark>` 的样式。

### 4. 备选：Pagefind / lunr

如果希望**完全不要服务端搜索**，可以在构建时（或后台发布时）生成 Pagefind 索引，前端 WASM 搜索。优点：零服务端开销、结果可高亮；缺点：索引需要随发布重建，与现在的 SSR 架构多一套流程。**当前规模（4 篇）用 FTS5 更简单。**

## 验收

- [ ] 搜正文中的词能命中（例：搜"西西弗斯"应命中签名/正文相关文章）。
- [ ] 搜索结果按相关度排序，标题命中的排在摘要命中的前面。
- [ ] 1000 篇假数据下，搜索响应 < 50 ms（`sqlite3` 里 `EXPLAIN QUERY PLAN` 应显示走 `posts_fts` 虚拟表，不是全表扫描）。
- [ ] 1–2 个字的查询不报错（回退 LIKE）。
- [ ] 含引号/星号的恶意输入不报 SQL 错误。
- [ ] 发布、编辑、删除文章后，索引同步（触发器生效）。
- [ ] 备份/恢复后索引一致（`INSERT INTO posts_fts(posts_fts) VALUES('integrity-check')` 无输出）。
