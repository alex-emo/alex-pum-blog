# OPT-06 图片资产瘦身

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 预计工时 | 2 h |
| 涉及文件 | `app/static/img/`、`app/templates/base.html`、`app/templates/partials/profile_card.html`、`app/config.py`（`SITE_AVATAR`） |
| 风险 | 低 |

## 问题

首页解码体积 ≈130 KB 里，**头像一项就占 87.3 KB（67%）**，而它在页面上只显示 28×28（顶栏）、36×36（移动端折叠条）、96×96（侧栏）。

| 资产 | 当前 | 实际显示尺寸 | 超标 |
| --- | --- | --- | --- |
| `avatar.png` | 87.3 KB / 256×256 PNG | 28 / 36 / 96 | **~9 倍** |
| `icon-512.png` | 300 KB | 512（仅 maskable/高 DPI） | 大 |
| `icon-maskable-512.png` | 163 KB | 512 | 可接受 |
| `apple-touch-icon.png` | 50 KB / 180×180 | 180 | 可接受 |

## 方案

### 1. 头像出多尺寸 WebP

```bash
# 以现有 avatar.png 为源，生成 96 / 192（2x）两档
for s in 96 192; do
  cwebp -q 82 -resize $s 0 app/static/img/avatar.png -o app/static/img/avatar-${s}.webp
done
```

同图 PNG 原图可保留为社交分享/OG 用，页面不再引用。

模板改成：

```html
<picture>
  <source type="image/webp" srcset="{{ asset_url('/static/img/avatar-96.webp') }} 1x,
                                      {{ asset_url('/static/img/avatar-192.webp') }} 2x">
  <img class="brand-avatar" src="{{ asset_url('/static/img/avatar-96.png') }}"
       alt="" width="28" height="28" decoding="async">
</picture>
```

> 头像在 `<a class="brand">` 里且 `alt=""`，属于装饰图，写 `alt=""` 正确，读屏会读站名文本。

### 2. 图标转 WebP

`icon-512.png` 300 KB 是 PNG 未优化（大概率是导出时 24-bit 无压缩）。转 WebP q=90 通常 < 40 KB；manifest 里同时声明 PNG 回退（部分老系统需要）。

```json
{ "src": "/static/img/icon-512.webp", "sizes": "512x512", "type": "image/webp", "purpose": "any" }
```

### 3. 顺带

- `avatar.png` 若确实是 256×256，96 px 显示已经是 2.67 倍超采样，直接出 96/192 即可。
- 所有静态图加 `decoding="async"`，非 LCP 图加 `loading="lazy"`（`profile_card.html` 已有）。
- `SITE_AVATAR` 是配置项，**改配置名会破坏现有 `.env`**，建议保留 `SITE_AVATAR` 指向 PNG 作为 fallback，模板里再拼 `-96.webp`，或新增 `SITE_AVATAR_WEBP` 可选覆盖。

## 验收

- [ ] 首页 `performance.getEntriesByType('resource')` 里图片解码总量 **< 20 KB**（优化前 87.3 KB）。
- [ ] 2x / 1x 屏幕上头像都不糊（Retina 下肉眼检查）。
- [ ] Lighthouse Performance 首页提升 ≥ 5 分。
- [ ] 浏览器无 404（`<picture>` 回退路径存在）。
