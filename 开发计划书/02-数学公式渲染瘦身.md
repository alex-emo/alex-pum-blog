# OPT-02 数学公式渲染瘦身

| 项目 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 预计工时 | 4 h |
| 涉及文件 | `app/static/vendor/mathjax/tex-mml-svg.js`、`app/templates/post.html`、`app/markdown_render.py` |
| 风险 | 中（公式渲染结果可能有细微差异，需逐篇回归） |

## 问题

`tex-mml-svg.js` 是 **2,120,598 字节（2.1 MB）** 的单文件，仅在 `has_math` 的文章加载，但一旦加载：

- 数学文章解码总量 **≈2217 KB**（HTML 18.7 + CSS 31.4 + avatar 87.3 + MathJax 2070.9 + JS 7.6）；
- 常见的"首屏 JS < 100 KB"预算被超了 **20 倍**；
- 移动端 4G 下这一项就要 3–8 秒。

## 方案

按代价从低到高：

### A. 换成 KaTeX（推荐，收益最大）

- 体积：`katex.min.js` + `katex.min.css` + 按需字体 ≈ **280 KB**（gzip 后 ~100 KB）。
- 现有模板已经用 `\( \)` / `\[ \]` 定界符，`pymdownx.arithmatex` 的 `generic: True` 输出通用定界符，切换只需换渲染脚本：

```html
<link rel="stylesheet" href="{{ asset_url('/static/vendor/katex/katex.min.css') }}">
<script defer src="{{ asset_url('/static/vendor/katex/katex.min.js') }}"></script>
<script defer src="{{ asset_url('/static/js/math.js') }}"></script>
```

`math.js` 里遍历 `.arithmatex`，`renderMathInElement` 或 `katex.render`。

- **注意**：`app/markdown_render.py` 里的 `_tidy_math`（把 `log2` → `\log_2`、多字母标识符包 `\mathrm{}`）是给 MathJax 擦屁股的。KaTeX 下同样受益，**保留**；但要逐篇比对渲染结果，特别是 `st` 这类短标识符。

### B. 继续用 MathJax，改按需组件（3 h，收益小）

用 `tex-svg.js`（只含 TeX 输入，不含 MathML 输入/输出的额外包）替代 `tex-mml-svg.js`，通常能降 30–40%。再配 `Output = 'svg'`。收益不如 A。

### C. 懒加载（可与 A/B 叠加，1 h）

用 `IntersectionObserver` 监听第一个公式位置，进入视口前 200 px 再插脚本。首屏无公式的文章可以直接省掉全部开销。

推荐组合：**A + C**。

## 验收

- [ ] 数学文章解码体积 < 800 KB（目标 < 500 KB）。
- [ ] 站点现有 4 篇文章里的公式逐一截图比对，无错位、无丢符号。
- [ ] `prefers-color-scheme: dark` 下公式颜色跟随正文（MathJax 原本自动继承 currentColor，KaTeX 需要 `color: inherit`）。
- [ ] 无 JS 时公式退化为可读的 `\(...\)` 原文（可接受，但需确认不会出现满屏乱码）。

## 实测结果

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| MathJax/KaTeX 资源 | 2070.9 KB | 待填 |
| 数学文章总解码体积 | 2217 KB | 待填 |

## 回滚

保留原 `vendor/mathjax/` 目录，`post.html` 的加载分支用环境变量开关（`MATH_RENDERER=katex|mathjax`），出问题一键切回。
